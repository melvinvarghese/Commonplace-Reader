### What the pinned API establishes

The [official viewer guide](https://developer.android.com/develop/ui/views/layout/pdf/implement-pdf-viewer) requires API 31 and SDK extension 13 for the full viewer. The actual beta01 AAR manifests declare minSdk 28 and the [release notes](https://developer.android.com/jetpack/androidx/releases/pdf) describe backported rendering. These are different claims: the comparison conservatively gates the full-viewer path on API 31 / extension 13, explicitly records Unsupported below it, and does not claim that the artifact cannot render at API 28. No app baseline change is made.

The exact [fragment](https://dl.google.com/dl/android/maven2/androidx/pdf/pdf-viewer-fragment/1.0.0-beta01/pdf-viewer-fragment-1.0.0-beta01-sources.jar), [viewer](https://dl.google.com/dl/android/maven2/androidx/pdf/pdf-viewer/1.0.0-beta01/pdf-viewer-1.0.0-beta01-sources.jar) and [core](https://dl.google.com/dl/android/maven2/androidx/pdf/pdf-core/1.0.0-beta01/pdf-core-1.0.0-beta01-sources.jar) source archives were inspected, rather than relying on older sample signatures. The host uses `onLoadDocumentSuccess(PdfDocument)`, experimental `onPdfViewCreated(PdfView)`, the real native selection listener, native search and native navigation/zoom. External-link activation is consumed, and the native annotation toolbox stays hidden through public lifecycle hooks; no OCR provider is supplied. The fragment owns its document and service lifecycle. A restricted annotation-resolution override was removed after strict lint identified it; no `RestrictedApi` suppression was added.

**Geometry is not proven.** `PdfPoint`/`PdfRect` use top-left page coordinates; `PageInfo` supplies page number, width, height and form widgets, but no original crop-box bounds or rotation metadata. `PdfView` exposes view/PDF transforms and native rectangular highlights, but these alone do not establish the approved original, unrotated PDF-point mapping on cropped/rotated inputs. This integration therefore does not invent a page box, rotation, quad, capture event or restored overlay. Durable capture/highlight display and PDF progress/bookmark jump-back are unavailable, and the required geometry gate is **FAIL / not demonstrated**, not rescued by successful rendering. This is a finding about the bounded integration, not a claim that all future AndroidX integrations are impossible. Source annotations and existing quotations remain independent durable records.

The flavor-local location codec preserves original metadata supplied to it, exact native JSON, zero-based page indexes and optional missing geometry. It rejects another candidate/EPUB/version; codec tests do not establish native geometric accuracy. Shared app-owned path/checksum verification runs before native opening, including the unsupported-platform path, and is also used by EPUB. Replacing bytes must retain writing but prevent any native application of saved coordinates.
